# remlax cleanup: diagnosis and plan

Note of 2026-10-29. It covers the remlax working tree: commit 777435a, plus
the removal of RTMB, the reworked README and the help pages regenerated by
roxygen2 8.1.1. These three changes are not committed yet.

The diagnosis comes from a full reading of the code, in four parts: the R
side, the Python orchestration layer (`fit.py`, `cli.py`, `inference.py`,
`serveur.py`), the model and the dense engines (`model.py`, `levels.py`,
`econome.py`, `blocs.py`, `lag.py`), then the MME engine, AI-REML, the
Bayesian route and the scan.

## Goal and constraints

Someone else must be able to read, understand and take over the code. Each
entry function must read as a sequence of named steps, and each step must be
a short function.

The cleanup changes no result. It keeps the following intact:

- the names and arguments of the exported R functions;
- the command-line options of the solver;
- the format of the data bundle exchanged between R and Python;
- the keys of `result.json` and the `out_*.bin` files;
- the order of the objective evaluations. The memo of `fit.py` keeps only
  one value per key, and AI-REML depends on it. Moving a call changes the
  number of evaluations and sometimes the last bit.

## Size and shape of the code

The package has 6 800 lines of R and 12 300 lines of Python. Most of the
difficulty sits in the files below.

| file | lines | main problem |
|---|---|---|
| `R/remlax.R` | 2 368 | the whole R side in a single file |
| `fit.py` | 1 890 | `_fit_reml_coeur` is 830 lines long, with sixteen steps |
| `mme.py` | 1 301 | `_evaluer` and `_derivees` are 190 to 200 lines long each |
| `ai.py` | 997 | `ai_reml_var` is 390 lines long, with closures that modify state |

Several defects recur throughout the code:

- Logbook comments. They report measurements, dates or past bugs instead of
  explaining the code. They sometimes refer to documents absent from the
  repository (`theorie_v2.md`, `note_remlax.md`, `mvD7`).
- French and English mixed in the internal names.
- Conventions recomputed in several places:
  - the kind of levels of a term, `tm.get("lvl") or ("fixed" if LK else "id")`, rewritten about twenty times;
  - the splitting of theta, rewritten four times in R and five times in Python;
  - the binary writing of the bundle, done twice in R;
  - four grammars to name a term column (`"terme:a"`).
- A fallback import block (relative `try`, absolute `except`) repeated 57
  times, so that the files also run as scripts.

## Dead code

These elements have no caller. The searches covered R/, tests/,
tests-python/ and inst/.

- R: `rx_here`, `rx_pkg_dir`, and a few local variables never read.
- `mme_cli.py`: the whole file. It imports symbols that no longer exist and
  would crash on loading.
- `ai.ai_reml`: replaced by `ai_reml_var`.
- `decoupage.ordre_niveaux_mme` and `_NiveauxCreux.appliquer_K`.
- `fit.py`, lines 641 and 644: a computation never used, hidden by a
  `noqa`.
- `fit.py`: a `fill_diagonal` with no effect and a `* 0` term.
- Unused imports and `compile_args` attributes never read.
- `core.py`: the chunked backward pass, which activates only with an
  environment variable that nothing sets.

The following elements call for a decision instead of a direct removal:
- `optimizer = "ai_theta"`, an old AI variant kept for comparison;
- `sparsity.py`, a diagnostic outside the fitting path;
- the Sigma structure `"fixed"`, reachable only from a test.

## Defects found during the reading

The cleanup does not fix them, since it guarantees identical results. Each
one will get a separate fix, with its own test, after the cleanup.

R side:

- The formula parsers evaluate `rank =`, `struct =` and `order =` in their
  own environment. `fa(trait, rank = rk)` then reads the local variable `rk`
  of the parser, and a user variable is not found.
- `rx_reml` with `trait` given as a column name and incomplete rows turns the
  name into a vector.
- `model.matrix` depends on the global option `na.action`.
- `rx_scan` names its folder to the second. Two scans started in the same
  second overwrite each other.

Python side:

- With weights, Wald, Kenward-Roger and the predictions rebuild V without the
  weights. This is probably wrong, to be checked by a test.
- `grad_rel` has two definitions. The final MME fallback to the dense engine
  therefore depends on `hessian = TRUE` or `FALSE`.
- The floor raised by the MME stays in place if the fit falls back to the
  dense engine, but the component table uses the original floor.
- The `jax.default_device` context is never closed on the error paths. The
  persistent server keeps it open.
- A term given only by `Kinv` is treated as K = I by the dense engines,
  without a message.
- The AI counter `nit` counts the points tried, not the iterations.
- The C kernel of the selected inversion falls back without a message to the
  NumPy loop, 5 to 15 times slower, when compilation fails.
- The `sep` structure on a residual section cannot work. Its path is not
  reachable today.

## Safety net

The net has the levels below.

1. End-to-end reference results
   (`remlax-validation/refacto/golden.R`). The script fits 36 cases that
   cover the paths of the solver:
   - the dense, low-memory, dense MME and sparse MME, and block engines;
   - the L-BFGS-B, AI and automatic optimisers, with and without restarts;
   - the us, fa, diag, ar1 × ar1 and spl2d structures, explicit terms,
     spatial lag and the `"none"` residual;
   - the PEV, Wald, Kenward-Roger, vpredict and prediction outputs;
   - the scan, LOCO and the exact refit;
   - the Bayesian route, evaluation at fixed theta, fixed parameters and
     the neighbourhood helpers.

   Each returned object is saved, with its `print()` and its `summary()`.
   Two captures of the same code are identical to the bit, printed timings
   excepted. The reference is stored in
   `refacto/reference_avant_nettoyage/`. After each step, the comparison
   must report "no difference".
2. The existing suites: 266 pytest tests and about 890 testthat checks.
3. For the steps that touch the MME and the AI, reference values of
   (f, g, AI) at fixed theta, for each inversion route (dense CPU, blocks,
   CHOLMOD, SuperLU, hybrid) and each term form. The step-by-step AI
   trajectory is added, because the optimum alone does not detect a change of
   path. This level remains to be written.

All comparisons run on CPU, with a single compute thread. The number of BLAS
threads shifts the likelihood at the sixth digit, and the GPU is not
deterministic. `verif_simulations` will be rerun at the end.

## Target architecture

### R side

`R/remlax.R` is split by step of the chain. Each file has an entry function
that chains named steps.

| file | content |
|---|---|
| `counts.R` | parameter counts and a single source for the splitting of theta |
| `term.R`, `residual.R`, `model.R` | `rx_term` (incidences, structure, kinship, levels), `rx_residual`, `rx_model` |
| `formula_random.R`, `formula_residual.R`, `spl2d.R` | the formula parsers, with their shared helpers (ar1 cells, 2D metrics, options) |
| `reml.R` | `rx_reml`: fixed effects, incomplete rows, spl2d, formula parsing, model, fit |
| `bundle_write.R`, `bundle_read.R` | a single binary writer, shared by `rx_fit`, `rx_scan` and `rx_predict`; reading the result |
| `python.R`, `launch.R`, `server.R` | find and check Python, launch the solver (server or subprocess), the persistent server |
| `fit.R` | `rx_fit`, with a single mapping table between R options and solver options, shared with `rx_fit_mme` |
| `predict.R`, `scan.R`, `design.R`, `ratios.R`, `bayes.R`, `lag.R`, `spatial.R`, `summary.R`, `validate.R` | one entry function and its steps |

Internal functions take a name of the form `.rx_<verb>_<object>`.
`rx_level_of` and `rx_scan_solver_args` carry the public prefix today without
being exported. The tests that call internal functions are updated at the
same time.

### Python side

- `cli.py`. `main` (375 lines) becomes a sequence of steps: read the
  arguments, prepare the process, read the bundle, fit, compute the
  inference, write. A single table of output arrays replaces the fifteen
  writes and the key blacklist. The device context goes through a `with`
  block.
- `fit.py` becomes a subpackage:
  - start: initial values, range sweep, loading bounds;
  - engines: `construire_moteur`, with a single contract for dense,
    low-memory, blocks and MME;
  - optimisation: the evaluation counter, L-BFGS-B, AI, leaving the floor,
    saddle point control;
  - polish, diagnostics and outputs;
  - `fit_reml`, written as the sequence of its sixteen steps.
- `inference.py` is split between the components (names, table, vpredict)
  and the fixed effects (Wald, Kenward-Roger, predictions), with a single
  inversion of V and a single covariance of theta.
- Model: a `terms.py` module that carries the kind of levels and a single
  theta layout, used by every engine. `levels.py` is split into stationary,
  metric and custom families.
- `mme.py` becomes a subpackage. Each inversion route (dense CPU, dense GPU,
  blocks, sparse, hybrid) becomes a class with the same interface, which
  removes five `if` chains. The cache of the last point, implicit today,
  becomes explicit. `remlax.mme` stays importable.
- `ai.py`: `ai_reml_var` is split into named functions (projection on the
  cone, active set, faces, Newton step, step search), with a small state
  object in place of the closures that modify their enclosing variables.
- `selinv.py` is split by section: ordering, CHOLMOD, SuperLU, supernodes,
  C kernel.

### Comments

Each comment keeps the purpose of the code in one or two sentences. The
measurements, dates and bug history go to `docs/notes_solveur.md`, a document
for developers that ships in the repository but not in the package archive.

## Order of work

Each step is a commit that passes the full net.

1. Commit the current state as a base: removal of RTMB, README and help
   pages. Open a `nettoyage` branch.
2. Remove the dead code, the unused imports and the variables never read.
3. Move the logbook comments to `docs/notes_solveur.md`.
4. R side: split into files, then step functions, then deduplication
   (binary writer, options table, column grammar, theta layout).
5. Python, orchestration: `cli.py`, then `fit.py`, then `inference.py`.
6. Python, model and dense engines.
7. Write the third level of the net, then restructure the MME, the AI and
   `selinv`.
8. Adapt the documentation, in particular the `engine` vignette, which
   describes the modules, and add an architecture guide for developers.
9. Fix the defects listed above, one commit and one test per defect. The
   results then change, and each change is explained.

The work spans several sessions. Steps 2 and 3 are quick and carry no risk.
Steps 5 and 7 need the most care.

## Decisions to make

1. The language of internal names and comments. The public API is in
   English, the comments are in French and the internal names mix both. I
   propose English internal names, consistent with the API, and English
   comments for a public package. Keeping French comments is possible, but
   the current mix must not stay.
2. The fate of `optimizer = "ai_theta"`, of `sparsity.py` and of the Sigma
   structure `"fixed"`.
3. The fallback import block. Removing it requires R to always launch the
   solver through `python -m remlax.cli`. Today R can launch it through the
   file path, which loads some modules twice.
4. The proposed order: cleanup with identical results first, fixes next.
